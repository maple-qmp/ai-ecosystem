## 检索要点（二手整理，非逐字）

### 定位与组件

- 一个二进制包含四件工具：运行时（替代 Node.js）、包管理器（替代 npm / Yarn / pnpm）、测试运行器（替代 Jest / Vitest，兼容 Jest API）、打包器（替代 esbuild / Vite / webpack）。
- 引擎用 Apple 的 JavaScriptCore（Safari 引擎），不是 Node.js 和 Deno 使用的 V8；原生运行 TypeScript 和 JSX。
- 内置大量 API：`Bun.serve()`（HTTP / WebSocket，1.4 实验性支持 HTTP/2、HTTP/3）、`Bun.SQL`（PostgreSQL / MySQL / SQLite）、Redis 客户端、`Bun.s3`、`bun:sqlite`、Bun Shell、`bun:ffi`、单文件可执行（`bun build --compile`，可交叉编译）。
- 官网自报：包管理器最高比 npm 快 30 倍；Express 基准 48,243 req/s 对 Node.js 25,181 req/s。官网列出的用户：Claude Code、Midjourney、Railway、Cursor；Anthropic 公告另提 Lovable。

### Zig → Rust 重写

- 动机：Zig 手动内存管理导致反复出现 use-after-free、double-free、错误路径泄漏，风格指南和代码审查拦不住；Rust 的所有权检查和 `Drop` 能直接消除这类问题。
- 方法：Jarred Sumner 用预发布版 Claude Fable 5，在 Claude Code 里跑约 50 个动态工作流、最多 64 个并行 Claude，连续 11 天；6,502 次提交，移植约 1,448 个 `.zig` 文件，最终合并 diff +1,009,272 行。每处改动由一个 Claude 实现，另两个独立上下文的“对抗式”评审检查；先做贴近原文的机械翻译，以现有测试套件为准。合并前消耗 59 亿未缓存输入 token、6.9 亿输出 token、720 亿缓存读取，按 API 价约 16.5 万美元；作者估计人工团队需约一年。
- 结果：六个平台上完整测试套件全部通过，未跳过或删除测试；引入 19 个已知回归，均已修复。所有可检测的内存泄漏消失（2,000 次进程内 `Bun.build()` 内存从 6,745 MB 降到 609 MB）。约 4% 代码在 `unsafe` 块内，多为 C / C++ 互操作。解析器 24/7 模糊测试约 1000 亿次。HTTP 吞吐 +2.8–4.8%，二进制体积约 -20%（Linux 88 MB → 70 MB）。之后计划逐步改成地道 Rust、减少 `unsafe`。
- 争议：Zig 作者 Andrew Kelley 2026-07-09 发文，认为问题出在 Bun 的工程实践而非语言，质疑性能与测试说法（称 LTO 等优化 Zig 本来就支持），批评 Bun 的风投节奏，并指控其管理方式；DevClass 报道标题称他把这次重写叫作“unreviewed slop”。Bun 曾长期资助 Zig 软件基金会，收购后资助结束。社区意见分化。

### 竞品与生态

- 服务端 JS 运行时：Node.js（OpenJS 基金会，V8）、Deno（Deno Land，V8 + Rust），以及边缘运行时 Cloudflare Workers（workerd）。
- 包管理：npm、pnpm、Yarn；测试：Jest、Vitest；打包：esbuild、Vite / Rolldown、webpack；类型检查：tsc / typescript-go；格式化：Prettier、oxfmt / Biome。
- AI 生态相关：Claude Code 以 Bun 单文件可执行分发；Vercel 平台支持 Bun 运行时；Mastra 等 TS Agent 框架可在 Bun 上运行。
