## 检索要点（二手整理，非逐字）

- **Next.js Adapter API**：Next.js 16（2025-10）以 alpha 发布，16.2（2026-03）转为稳定；与 OpenNext、Netlify、Cloudflare、AWS Amplify、Google Cloud 合作制定。构建时产出带类型、带版本的应用描述，任何人都可基于公开 API 写 adapter，官方用公开测试套件判定兼容。OpenNext 的 AWS / Cloudflare adapter 在同一 monorepo 开发，Netlify adapter 开发中，预计 2026 年底前全部发布。
- **AI SDK**：AI Gateway 是 AI SDK 的默认全局 provider，`"creator/model-name"` 形式的模型字符串会自动走 Vercel AI Gateway；可通过给 `globalThis.AI_SDK_DEFAULT_PROVIDER` 赋值改成其他 provider，或直接传 provider 实例（如 `@ai-sdk/openai`）。
- **Workflow DevKit**：存储与队列抽象成“World”。Vercel World 是托管选项；自托管用 Postgres World（`@workflow-worlds/postgres`，PostgreSQL 存储 + pg-boss 队列），通过环境变量 `WORKFLOW_TARGET_WORLD` 和 `DATABASE_URL` 选用；也可以自己实现 World。Worlds 页面显示 Postgres World 兼容性“Passing”，E2E 304/312 通过。观测面板 `@workflow/web` 可读取 Postgres World。
- **Turborepo**：Remote Cache 有公开的 OpenAPI 规范（`/artifacts/{hash}` 等端点，Bearer token 认证），任何兼容服务器都可接入；用 `TURBO_API`、`TURBO_TOKEN`、`TURBO_TEAM` 指向自建服务（社区实现如 ducktors/turborepo-remote-cache）。
- **Chat SDK**（npm `chat`）：MIT 协议，一套代码对接 Slack、Teams、Discord、Google Chat、Telegram、GitHub、Linear；adapter 在 `@chat-adapter/*` 下。
- **agent-browser**：Vercel Labs 出品，Apache-2.0，Rust 写的面向 AI Agent 的浏览器自动化 CLI，首次运行下载 Chrome for Testing。

## 依赖分级（调研结论）

- **完全独立**：SWR、Satori、`@vercel/ncc`、`@vercel/nft`、`serve`、`ms`、Geist 字体、Streamdown、AI Elements、Chat SDK、agent-browser
- **默认连 Vercel，可改配置脱离**：AI SDK（默认 provider = AI Gateway）、Turborepo（默认远程缓存 = Vercel）、Workflow DevKit（Vercel World / Postgres World）、Flags SDK（Flags Explorer 属 Vercel 工具栏）、`mcp-handler`（需自备 Redis 才能续传）
- **自托管可用但多实例需自己补组件**：Next.js（共享缓存 handler、加密密钥、deploymentId、流式代理）
- **本身就是 Vercel 服务的客户端**：`@vercel/analytics`、`@vercel/speed-insights`、`@vercel/blob`、`@vercel/edge-config`、`@vercel/functions`、`@vercel/oidc`、`@vercel/sandbox`、`@ai-sdk/gateway`、Vercel CLI、v0；`@vercel/kv`、`@vercel/postgres` 已停用并迁往 Upstash / Neon
