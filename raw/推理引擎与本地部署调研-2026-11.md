# 推理引擎与本地部署调研（2026-11）

一句话：梳理 L3 层的推理与训练基础设施，分三块。一是数据中心推理引擎 vLLM、SGLang、TensorRT-LLM 及其上的编排层 NVIDIA Dynamo、llm-d；二是本地推理 llama.cpp / GGUF、Ollama、LM Studio；三是大规模训练框架 DeepSpeed、Megatron。另外整理三项横跨各引擎的推理技术：KV cache 管理（PagedAttention、RadixAttention、前缀缓存、分层卸载）、推测解码、预填充 / 解码分离。2026 年的主线是开源推理引擎的公司化（Inferact、RadixArk 分别获 1.5 亿、1 亿美元种子轮）和本地推理的平台化（ggml.ai 并入 Hugging Face，Ollama 加入云端模型与 B 轮）。检索日期 2026-11-05。

## 一、数据中心推理引擎

### vLLM

- 2023 年在 UC Berkeley Sky Computing Lab 开发，核心是 PagedAttention；发布前已在 LMSYS 的 Chatbot Arena 与 Vicuna Demo 上运行两个月。
- 发布博客数据：比 Hugging Face Transformers 吞吐高 14–24 倍，比 HF TGI 高 2.2–2.5 倍；现有系统因碎片和过度预留浪费 60%–80% 的 KV cache 显存。
- 引擎演进（二手报道）：v0.8.0（2025-03）起 V1 引擎成为默认；v0.10.0 开始清理 V0；v0.11.0（2025-10-02）彻底移除 V0。
- 2025-05 成为 PyTorch Foundation 托管项目（与 DeepSpeed 一起，是 PyTorch 之外首批托管项目；二手报道，来自 PyTorch Foundation 年度回顾）。
- README 现状：2000+ 贡献者；支持 200+ 种 Hugging Face 模型架构；功能包括连续批处理、分块预填充、前缀缓存、CUDA/HIP 图、FP8 / MXFP4 / NVFP4 / INT4 / GPTQ / AWQ / GGUF 等量化、FlashAttention / FlashInfer / FlashMLA 等注意力内核、推测解码（n-gram、suffix、EAGLE、DFlash）、torch.compile、预填充 / 解码 / 编码分离、张量 / 流水线 / 数据 / 专家 / 上下文并行、结构化输出（xgrammar、guidance）、工具调用与推理解析器、OpenAI 兼容服务器以及 Anthropic Messages API 与 gRPC、多 LoRA；硬件覆盖 NVIDIA、AMD、Intel GPU 与 x86 / ARM / PowerPC CPU，另有 TPU、Gaudi、昇腾、Apple Silicon 等插件。
- 公司化（二手报道）：Inferact 于 2026-01-22 宣布成立，种子轮 1.5 亿美元、投后估值 8 亿美元，Andreessen Horowitz 与 Lightspeed 领投（另有报道称 Altimeter 领投，说法不一），Sequoia、Altimeter、Redpoint、真格基金参投。CEO Simon Mo（vLLM 原始作者之一），联合创始人 Woosuk Kwon、Kaichao You、Roger Wang、Ion Stoica（Databricks 联合创始人、Berkeley Sky Computing Lab 负责人）。目标是将 vLLM 商业化，vLLM 本身保持开源。
- PyPI：2026-11-02 发布 0.33.0。

### SGLang

- 2024-01-17 由 LMSYS 发布博客介绍：前端是嵌入 Python 的 LLM 程序语言，后端提出 RadixAttention（用基数树自动复用 KV cache）；在 agent、推理、抽取、对话、few-shot 任务上吞吐最高提升 5 倍。
- README 现状：定位为面向大语言模型、视觉语言模型和扩散模型的推理框架，针对 agent 工作负载、大规模服务和 RL rollout 优化；内置 SGLang Diffusion（图像、视频生成）。由非营利组织 LMSYS 托管。
- 硬件：NVIDIA（B200 / B300 / GB200 / GB300、H100 / H200 / H20、A100、RTX 系列、DGX Spark、Jetson）、AMD Instinct MI300X–MI355X、Google TPU（SGLang-TorchTPU、SGL-JAX）、Intel GPU / CPU、Apple Silicon、华为昇腾、摩尔线程；在接入中的有 AWS Trainium、阿里平头哥 PPU、寒武纪、高通、沐曦、海光、天数智芯等。
- 周边生态：SGLang Omni（语音 TTS / ASR）、SpecForge（训练推测解码草稿模型）、RL 与后训练框架 Miles、slime、AReaL、Tunix、verl 用 SGLang 生成 rollout；部署编排 SMG、RBG、llm-d、Ray Serve、NVIDIA Dynamo。
- 致谢中写明借鉴并复用了 Guidance、vLLM、LightLLM、FlashInfer、Outlines、LMQL 的设计与代码。
- 长期贡献者可申请 Cursor、Claude Code、OpenAI Codex 的使用赞助。
- SGLang Summit 2026：2026-11-12 至 13，旧金山。
- 公司化（二手报道）：2026-01-21 TechCrunch 援引消息称 SGLang 团队拆分成立 RadixArk，Accel 领投、估值约 4 亿美元，此前有 Intel CEO 陈立武等天使投资。2026-05-05 RadixArk 正式宣布 1 亿美元种子轮、投后估值 4 亿美元，Accel 领投，Spark Capital、NVentures（NVIDIA 风投）、HOF Capital 参投；联合创始人 Ying Sheng、Banghua Zhu。公司称 SGLang 支撑的集群合计 40 万块以上 GPU；同时开发强化学习框架 Miles。
- PyPI：2026-10-30 发布 0.5.23。

### TensorRT-LLM

- NVIDIA 的 LLM 与视觉生成模型推理优化库：常见算子（attention、GEMM、MoE）定制内核，加上预填充 / 解码分离、宽专家并行、推测解码等运行时优化，只面向 NVIDIA GPU。
- 2025-03-22 完全开源，开发转到 GitHub（README 新闻）。
- 1.0（2025-09-24，二手报道 + PyPI）：基于 PyTorch 的架构成为稳定默认，LLM API 稳定；此前 TensorRT 引擎构建流程不再是默认。
- 可与 NVIDIA Dynamo、Triton Inference Server 集成。
- 2026 年技术博客：DeepSeek-V3.2 / V4 在 Blackwell 上的优化、稀疏注意力、Skip Softmax Attention、NVL72 上的分布式权重数据并行（DWDP）、agent 应用与引擎联合优化、agentic 服务评测（trace 回放）、视频生成加速、KV cache 压缩（2026-10-14）。
- 带遥测，CI 和测试环境自动关闭；遥测代码开源可审计。

### NVIDIA Dynamo

- 开源的数据中心级推理栈，定位是推理引擎之上的编排层：不替代 SGLang、TensorRT-LLM、vLLM，而是把它们组织成多节点协同的推理系统。
- 能力：预填充 / 解码分离、KV 感知路由（避免重复预填充）、多层 KV 缓存、按延迟 SLA 自动扩缩、快速冷启动；面向 LLM、推理模型、多模态和视频生成。
- 用 Rust 写性能部分，Python 负责扩展；Apache-2.0；160+ 社区贡献者。
- KV 传输用 NIXL（NVIDIA Inference Xfer Library），显存到显存直传、非阻塞。
- 版本：PyPI 最早包 2025-03-12；1.0 于 2026-03 GTC 期间发布，称已投产（二手报道，报道列出的采用方包括 CoreWeave、Nebius、Together AI、Cursor、Perplexity、PayPal、Pinterest、字节跳动、美团、阿斯利康；NVIDIA 称在 GB200 NVL 上推理性能最高提升 7 倍）；最新稳定版 1.6.1。

### llm-d

- 面向 Kubernetes 生产部署的高性能分布式推理服务栈，CNCF 沙箱项目（二手报道称 2026-03-24 入选），由 Red Hat、Google Cloud、IBM Research、CoreWeave、NVIDIA 发起。
- 与 Dynamo 定位相同：在 vLLM、SGLang 等模型服务器之上做编排。能力包括前缀缓存感知与负载感知路由、预测延迟调度、分层 KV 卸载（CPU、磁盘）与全局 KV 索引、预填充 / 解码分离与宽专家并行、面向 agent 的会话感知路由与 Responses API 状态、多租户 QoS、SLO 感知自动扩缩、OpenAI 兼容 Batch API。
- README 列出的效果（来自合作方博客）：前缀缓存感知路由比轮询吞吐高 3 倍、首 token 快 2 倍（Llama 3.1 70B，4×MI300X）；预填充 / 解码分离比标准 vLLM 每秒 token 数最多高 70%（GPT-OSS，B200，AWS）；分层 KV 卸载在 250 并发时吞吐提升 13.9 倍（4×H100）。

## 二、本地推理

### llama.cpp 与 ggml

- Georgi Gerganov 于 2022-09 开始写张量库 ggml；此前写过 whisper.cpp（OpenAI Whisper 的 C/C++ 实现）。llama.cpp 于 2023-03 开始开发，首个版本 2023-03-10，用纯 C/C++ 实现 Llama 推理（二手报道，Wikipedia）。
- 2023 年成立公司 ggml.ai 支持开发（二手报道）。
- README 现状：MIT 协议；目标是在各种硬件上本地或云端以最少配置、最佳性能运行 LLM / VLM；纯 C/C++ 无依赖，Apple Silicon 一等公民（NEON、Accelerate、Metal），x86 AVX / AVX512 / AMX，RISC-V，1.5–8 bit 整数量化，CUDA、HIP、MUSA、Vulkan、SYCL、CANN（昇腾）、OpenCL（Adreno）、Hexagon（骁龙）等后端，CPU+GPU 混合推理以运行超出显存的模型。
- 新的统一命令 `llama cli` / `llama serve`（OpenAI 兼容 API 服务器，带内置 Web UI），可直接从 Hugging Face 拉取 GGUF 模型；安装入口 llama.app。
- 2026-02-20 ggml.ai 团队加入 Hugging Face，财务条款未披露。HF 博客说明：Georgi 团队继续 100% 时间维护 llama.cpp，保有技术方向和社区的完全自主权；项目保持 100% 开源、社区驱动；技术重点是从 transformers 库「几乎一键」把新模型带到 llama.cpp，以及改进 ggml 系软件的打包和用户体验。HF 团队中原本就有 llama.cpp 核心贡献者 Son（ngxson）和 Alek（allozaur）。

### GGUF

- ggml 系推理引擎使用的模型文件格式，二进制、单文件，设计目标是快速加载保存、易读；模型通常在 PyTorch 等框架中开发，再转换成 GGUF。
- 是 GGML、GGMF、GGJT 的后继格式；与 GGJT 的关键区别是超参数改用键值结构（元数据），可以加新信息而不破坏兼容。
- 设计目标：单文件部署、可扩展、兼容 `mmap`、易用（任何语言用少量代码即可读写）、信息完整。
- 命名约定 `[<Sidecar>]<BaseName><SizeLabel><FineTune><Version><Encoding><Type><Shard>.gguf`；Sidecar 可为 `mmproj`（多模态投影器）或 `mtp`（多 token 预测头，用作推测解码草稿模块）。
- 首次发布于 2023-08（二手报道）。
- vLLM 也支持加载 GGUF 量化模型。

### Ollama

- 公司：Y Combinator 2021 冬季批次，创始人 Jeffrey Morgan、Michael Chiang；两人此前做过 Kitematic，2015 年卖给 Docker（二手报道）。
- 主要用 Go 编写，早期通过 CGo 调用 llama.cpp 作为推理后端；2025 年中开始转向自研引擎，有评论认为因此引入了 llama.cpp 已修复过的问题（二手报道，评论性来源）。
- README 现状：「Start building with open models」，本地或云端运行开放模型；macOS / Windows / Linux / Docker 安装；官方 Python 与 JS 库。
- `ollama launch` 一键把 Ollama 接入现有编程 Agent：Claude Code、Codex、Copilot CLI、DeepSeek Harness、Droid、OpenCode、OpenClaw 等（二手报道称 2026-01 推出）。
- Anthropic 兼容：文档称支持 Anthropic Messages API 的一个子集，可把 Claude Code 等 Anthropic 客户端接到 Ollama 的本地或云端模型；云端可直接请求 `https://ollama.com/v1/messages`，无需安装 Ollama。（本库已有的 Claude 调研记录为 v0.14.0 起，2026-01。）
- Ollama Cloud：用 API key 直接调用云端模型，也支持 OpenAI、Anthropic 客户端，无需下载模型或应用；模型名带 `:cloud` 后缀（二手报道）。2026-08-31 推出按 token 计费的云端套餐，本地软件仍免费、MIT 协议（二手报道）。
- 融资（二手报道）：2026-07-09 宣布 6500 万美元 B 轮，Theory Ventures 领投，Benchmark、8VC、Y Combinator、Pace Capital 等参投；此前 A 轮 1500 万美元由 Benchmark 的 Peter Fenton 领投，累计融资 8800 万美元；用户约 890 万开发者（自 1 月起翻倍）；未披露估值。

### LM Studio

- Element Labs, Inc.（纽约布鲁克林）开发的桌面应用，Yagil Burowski 于 2023 年创办（二手报道）。
- 双引擎：GGUF 模型走定制的 llama.cpp 分支，MLX 模型走 Apple MLX 引擎（仅 Apple Silicon），两类模型可同时加载（二手报道）。
- 提供 OpenAI 兼容 API（`http://localhost:1234/v1`）；0.4.x（2026 年初）加入 Anthropic 兼容的 `/v1/messages` 端点，可用 `ANTHROPIC_BASE_URL` 接 Claude Code（二手报道，具体版本说法不一，0.4.1 或 0.4.9）。
- 2025-07-08 起个人和工作使用均免费，无需申请；另有付费企业 / 团队版（SSO、模型管控）（二手报道）。
- 0.4 加入无界面守护进程 `llmster`，用于服务器部署（二手报道，日期说法不一，多数称 2026-01）。
- 命令行工具 `lms`（基于 lmstudio.js）随 LM Studio 0.2.22 及以后版本附带，可查看状态、启动本地 API 服务器、加载模型。

## 三、大规模训练框架

### DeepSpeed

- 微软开源的分布式训练优化库，核心 ZeRO：把优化器状态、梯度、参数切分到各数据并行进程，消除冗余副本（2020 年微软研究院博客首发）。
- README 称曾支撑 MT-530B（与 Megatron 合作训练的 Megatron-Turing NLG 530B）等当时最大的语言模型；是微软 AI at Scale 计划的一部分。
- 治理（二手报道）：2025 年初移交 Linux Foundation AI & Data（1 月或 2 月，说法不一）；2025-05 成为 PyTorch Foundation 托管项目。仓库已迁到 `deepspeedai/DeepSpeed`。
- 近况：2025 年推出 DeepCompile（编译器优化）、AutoTP（自动张量并行）、ALST（与 Snowflake 合作的百万 token 级长序列训练）、DeepNVMe、ZenFlow（无停顿卸载）、SuperOffload（面向超级芯片的卸载）；2025-12 Core API 更新（PyTorch 风格 backward、低精度主权重）；2026-03 SuperOffload 获 ASPLOS 2026 最佳论文荣誉提名；2026-05 支持 Muon 优化器、AMD GPU 上 ZeRO-3 的 System DMA。
- PyPI：0.19.9，2026-10-29。

### Megatron-LM / Megatron Core

## 四、横跨各引擎的推理技术

### KV cache 管理

- 自回归解码中每个输入 token 产生的 key / value 张量留在显存里用来生成后续 token，即 KV cache；它大而动态，是 LLM 服务的显存瓶颈。
- PagedAttention（vLLM，2023）：借鉴操作系统虚拟内存分页，把 KV cache 切成块，块在显存中不必连续。
- RadixAttention（SGLang，2024）：请求结束后不丢弃 KV cache，把提示和生成结果的 KV 存在基数树里，自动做前缀匹配和复用；与连续批处理、PagedAttention 兼容。
- 前缀缓存：vLLM 等引擎后来也内置；多轮对话、agent 这类共享长前缀的负载收益最大。
- 分层卸载与跨实例共享：LMCache 支持 KV 卸载（跨请求复用前缀）和跨引擎 / GPU 传输；llm-d、Dynamo 做多层 KV 缓存和 KV 感知路由；TensorRT-LLM 2026-10 发布 KV cache 压缩。

### 推测解码

- 用便宜的方式先猜多个 token，再由目标模型一次并行验证，输出分布不变（无损），降低解码延迟。
- 方法：n-gram / 提示查找、草稿小模型、EAGLE 系列（在目标模型特征层上训练轻量草稿头）、Medusa、多 token 预测（MTP）头、suffix 解码、DFlash 等。
- EAGLE README：EAGLE 比普通解码快 3 倍（13B），比 Lookahead 快 2 倍，比 Medusa 快 1.6 倍；EAGLE-2 比普通解码快 4 倍、比 EAGLE-1 快 1.4 倍；EAGLE-3（2025-03-19 发布，NeurIPS'25 收录）比普通解码快 5.6 倍、比 EAGLE-1 快 1.8 倍，去掉特征预测约束，改用低、中、高层语义特征融合。
- 引擎支持：vLLM（n-gram、suffix、EAGLE、DFlash）；SGLang（EAGLE，配套 SpecForge 训练草稿模型）；TensorRT-LLM（含 n-gram 自动启用、与引导解码结合）；GGUF 规范为 MTP 草稿模块定义了 `mtp` sidecar 文件。

### 预填充 / 解码分离

- 预填充（处理整段提示，计算密集）和解码（逐 token 生成，访存密集）放到不同的 GPU 池，各自独立扩缩；预填充 GPU 产生的 KV cache 要传到解码 GPU。
- 实现：NVIDIA Dynamo、llm-d 在编排层做；vLLM（预填充、解码、编码分离）、SGLang、TensorRT-LLM 在引擎层支持。传输库包括 NIXL（Dynamo、Ray Serve 的 NIXLConnector）和 LMCache（LMCacheConnectorV1）。
- 效果（llm-d README 引用合作方数据）：AWS 上 GPT-OSS / B200 每秒 token 数最多高 70%；Oracle 上 AMD MI300X 吞吐提升 10–30%。
