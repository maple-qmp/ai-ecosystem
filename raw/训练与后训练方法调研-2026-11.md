# 训练与后训练方法调研（2026-11）

一句话：梳理 L3 层训练一侧的方法与工具。方法按训练流水线排列：预训练 → 监督微调（SFT）→ 偏好对齐（RLHF、DPO）→ 推理能力强化学习（GRPO、RLVR）→ 知识蒸馏，并核实参数高效微调 LoRA / QLoRA 与量化（GPTQ、AWQ、LLM.int8()、NF4）。工具收录 Hugging Face 的 TRL、Unsloth、Axolotl、LLaMA-Factory、字节跳动 Seed 发起的 verl。2025–2026 年的主线是后训练的重心从“偏好对齐”转向“可验证奖励的强化学习”：DeepSeek 的 GRPO 和 Ai2 的 RLVR 成为推理模型的标准配方，各家工具都把 GRPO 做成一等功能，verl 这类“训练 + 推理引擎 rollout”的 RL 框架成为独立一类。检索日期 2026-11-05。

## 一、训练方法

### 预训练（Pretraining）

- 在海量无标注文本上做下一个 token 预测（自回归语言建模），得到基座模型；绝大部分算力花在这一阶段，后续阶段都在它的基础上做。
- 规模与数据配比由规模定律指导（本库已有概念页）。大规模预训练依赖 Megatron Core、DeepSpeed、PyTorch FSDP 等并行框架（见本库推理引擎调研）。
- 工具侧也有覆盖：LLaMA-Factory 的「Supported Training Approaches」表第一行即 Pre-Training（全量、冻结、LoRA、QLoRA 等均支持）；Unsloth 的特性列表写明支持 pretraining；Axolotl 2025-12 为 FSDP2 预训练加入分布式 Muon 优化器。
- 继续预训练（continual pre-training）：在已有基座上用领域语料接着做预训练，LLaMA-Factory 写作「(Continuous) pre-training」。

### 监督微调（SFT）

- 用人工撰写或筛选的「指令—回答」示范数据，以交叉熵损失微调预训练模型，让它学会遵循指令、对话格式和工具调用格式。
- InstructGPT 把它作为三阶段流程的第一步：先收集标注员示范，用监督学习微调 GPT-3，再做奖励模型和 RLHF。
- DPO 参考实现同样先做 SFT，理由是让偏好数据落在策略模型的分布内。
- DeepSeek-R1 的流水线含「两个 SFT 阶段」作为推理和非推理能力的种子；R1-Zero 则跳过 SFT 直接做 RL。
- Tülu 3 的流水线是 SFT → DPO → RLVR（二手：搜索摘要）。
- 工具：TRL 的 `SFTTrainer`、Axolotl、LLaMA-Factory、Unsloth、verl 均支持 SFT。Axolotl 2026-09 加入 Dynamic Fine-Tuning（DFT，按 token 概率加权 SFT 损失）。

### RLHF（基于人类反馈的强化学习）

- InstructGPT（OpenAI，2022）确立的大模型对齐流程：① 用标注员示范做 SFT；② 收集标注员对多个输出的排序，训练奖励模型；③ 以奖励模型为奖励、用强化学习（PPO）继续微调 SFT 模型。
- InstructGPT 的核心结果：在其提示分布上，1.3B 参数的 InstructGPT 的输出比 175B 的 GPT-3 更受人偏好，参数少 100 倍；真实性提升、有害输出减少，公开 NLP 数据集上的性能退化很小。
- PPO 需要同时维护策略、参考、奖励、价值（critic）四个模型，工程复杂、显存开销大，这是后来 DPO、GRPO 等方法要解决的问题。
- 工具：LLaMA-Factory 支持 Reward Modeling、PPO；verl 支持 PPO；TRL 以前提供 PPO trainer，现在的 README 以 SFT / GRPO / DPO / KTO 为主；verl 论文 HybridFlow 的标题即「A Flexible and Efficient RLHF Framework」。

### DPO（直接偏好优化）

- Rafailov 等（斯坦福），NeurIPS 2023。论文标题「Your Language Model is Secretly a Reward Model」：证明 RLHF 中「奖励模型 + KL 约束的强化学习」目标存在闭式最优解，可以把奖励写成策略与参考模型的对数概率比，于是直接在偏好对（优选 / 劣选回答）上用一个分类式损失训练策略，不需要单独训练奖励模型，也不需要在训练中采样。
- 参考实现的流水线：① 在目标数据上做 SFT；② 在偏好数据上做偏好学习（最好与 SFT 数据同分布）。
- 参考实现后来加入 conservative DPO（标签平滑，假设部分偏好标注是反的）和 IPO。
- 衍生方法：IPO、KTO、ORPO、SimPO、GDPO 等。LLaMA-Factory 2023-08-11 支持 DPO，之后陆续加入 ORPO（2024-03）、KTO（2024-05）、SimPO（2024-05）；Axolotl 支持 DPO、IPO、KTO、ORPO，2026-02 加入 GDPO（Generalized DPO）；TRL 有 `DPOTrainer`、`KTOTrainer`。

### GRPO（组相对策略优化，DeepSeek）

- 由 DeepSeek 在 DeepSeekMath 论文（2024-02，arXiv 2402.03300）中提出：DeepSeekMath-RL 7B 在 DeepSeekMath-Instruct 7B 基础上用 GRPO 训练。
- 思路：对同一个问题采样一组回答，用组内奖励的均值与标准差做归一化，得到每个回答的相对优势，替代 PPO 中的价值（critic）模型，因此省掉一个与策略同等规模的模型。TRL README 的说法是「比 PPO 更省显存」。
- DeepSeek-R1（2025-01，arXiv 2501.12948）用大规模 RL 训练推理能力：R1-Zero 直接在基座模型上做 RL、不经过 SFT，自发出现自我验证、反思、长思维链；README 称这是「第一个公开验证 LLM 推理能力可以纯靠 RL 激发、无需 SFT 的研究」。R1-Zero 有无限重复、可读性差、语言混杂的问题，R1 在 RL 前加入冷启动数据，流水线为两个 RL 阶段 + 两个 SFT 阶段，数学、代码、推理上与 OpenAI-o1 相当。TRL README 说明 GRPO「被用于训练 DeepSeek 的 R1」。
- 改进与变体：DAPO（字节 Seed + 清华 AIR，2025-03，Decoupled Clip and Dynamic sAmpling Policy Optimization，基于 Qwen2.5-32B 基座在 AIME 2024 上拿到 50 分，超过 DeepSeek-R1-Zero-Qwen-32B，训练步数少一半，完全基于 verl）、Dr.GRPO、GSPO、VAPO（字节，基于价值的 PPO 改进，AIME 2024 60.4）等。
- 工具：TRL `GRPOTrainer`；Unsloth（gpt-oss 20B GRPO 笔记本称快 2 倍、省 80% 显存）；Axolotl 2025-02 加入 GRPO，2026-04 加入异步 GRPO（步时最多快 58%）；verl 支持 GRPO、DAPO、DrGRPO、GSPO 等；open-instruct 用 `grpo_fast.py` 跑 RLVR。

### RLVR（可验证奖励强化学习）

- 名称出自 Ai2 的 Tülu 3 论文（2024-11，arXiv 2411.15124，二手：搜索摘要）：作为后训练的最后阶段，只在模型的回答被程序验证为正确时给奖励，用于数学、精确指令遵循等答案可检验的技能。Tülu 3 基于 Llama 3.1 基座，开放权重、数据、代码和评测工具。
- 与 RLHF 的区别：奖励来自规则或程序（答案比对、单元测试、格式检查），不来自学习到的奖励模型，因此不容易被「奖励黑客」利用，也不需要人工偏好标注。DeepSeek-R1 的 RL 同样以基于规则的准确性奖励为主（二手，论文原文未打开）。
- 算法上与 GRPO / PPO 正交：RLVR 说的是奖励从哪来，GRPO 说的是怎么用奖励更新策略。open-instruct 用 GRPO 实现 RLVR；verl 的特性列表写作「function-based reward (verifiable reward) for math, coding」；TRL 提供 `accuracy_reward`（依赖 math-verify）和面向推理模型的 `reasoning_accuracy_reward()`。
- open-instruct README：仓库提供「DPO、偏好微调和可验证奖励强化学习（RLVR）」代码；Olmo MoE 模型改用 MILES + OLMo-core 集成，稠密模型仍可用 DeepSpeed/vLLM GRPO 流程。

### 知识蒸馏（Knowledge Distillation）

- Hinton、Vinyals、Dean 2015 年论文（arXiv 1503.02531，二手：搜索摘要）：用大模型（或集成）输出的「软目标」——带温度的 softmax 概率分布——训练小模型，把知识压缩进部署成本更低的网络。
- 大模型时代的常见做法是「数据蒸馏」：用强模型生成回答或推理轨迹，再用这些数据对小模型做 SFT。DeepSeek-R1 用 R1 生成的推理数据（约 80 万条样本）微调了 6 个基于 Qwen2.5 与 Llama3 的稠密模型（1.5B、7B、8B、14B、32B、70B），README 称把大模型的推理模式蒸馏给小模型，效果好于在小模型上直接做 RL；DeepSeek-R1-Distill-Qwen-32B 在多项基准上超过 OpenAI-o1-mini。
- R1 的 MIT 许可明确允许用于蒸馏训练其他 LLM。
- 工具：verl 的 VeRL-Tinker（2026-08）可在 verl 管理的 GPU 上跑 SFT、RL 和蒸馏。

## 二、参数高效微调与量化（核实种子页）

### LoRA

- 作者：Edward J. Hu、Yelong Shen、Phillip Wallis、Zeyuan Allen-Zhu、Yuanzhi Li、Shean Wang、Lu Wang、Weizhu Chen（微软）；arXiv 2106.09685（2021）。
- 方法：冻结原权重，为权重矩阵学习一对低秩分解矩阵，从而大幅减少可训练参数；存储需求大幅下降，部署时可以高效切换任务，而且不引入推理延迟（低秩矩阵可合并回原权重）。
- README 数据：GLUE 上 RoBERTa base 全量微调训练 125M 参数，LoRA 只训练 0.8M，平均分 87.24 对 86.40；DeBERTa XXL 1.5B 对 4.7M，91.32 对 91.06。效果好于 adapter、prefix-tuning 和全量微调。
- 官方包 `loralib` 只支持 PyTorch；2023-02 起 Hugging Face 的 PEFT 库支持 LoRA。
- 变体（LLaMA-Factory 支持列表）：DoRA、LoRA+、rsLoRA、PiSSA、LoftQ、LongLoRA；Axolotl 2026 年加入 MixLoRA（在稠密模型上加路由的 LoRA 专家）、MoE 专家权重上的 ScatterMoE LoRA、NVFP4 LoRA。
- 多 LoRA 服务：vLLM 支持多 LoRA（见本库推理引擎调研）。

### QLoRA

- Dettmers 等（华盛顿大学 UW NLP），arXiv 2305.14314（2023-05）。把梯度反向传播穿过冻结的 4-bit 量化预训练模型，进入 LoRA 适配器；单张 48GB GPU 可以微调 65B 模型，同时保持 16-bit 全量微调的任务性能。
- 三项省显存创新：4-bit NormalFloat（NF4，对正态分布权重在信息论上最优的数据类型）、双重量化（对量化常数再量化）、分页优化器。
- 衍生的 Guanaco 模型在 Vicuna 基准上达到 ChatGPT 的 99.3%，单 GPU 微调 24 小时。
- 依赖 bitsandbytes 做量化，集成进 PEFT 与 transformers。

### 量化

- GPTQ（IST Austria，ICLR 2023，arXiv 2210.17323）：「生成式预训练 Transformer 的精确训练后压缩」，把 OPT、BLOOM 压到 2/3/4 bit，支持权重分组。
- AWQ（MIT Han Lab，arXiv 2306.00978）：激活感知的低比特（INT3/4）权重量化，支持指令微调模型和多模态模型，提供 CUDA 推理内核与 TinyChat 端侧推理。
- bitsandbytes：PyTorch 的 k-bit 量化库，三项功能——8-bit 优化器（分块量化，以很小的显存保持 32 位性能）；LLM.int8()（向量级量化，大部分特征用 8 bit，离群值用 16 bit 矩阵乘单独处理，推理显存减半且无性能下降）；QLoRA / 4-bit 量化训练。要求 PyTorch 2.4+。
- 训练与量化的交叉：量化感知训练（QAT）——Axolotl 2025-05 加入 QAT，2025-08 加入 NVFP4 QAT，支持 int8 / int4 / FP8 / NVFP4 / MXFP4；FP8 混合精度训练（Axolotl 经 torchao，Unsloth 也支持 FP8）；LLaMA-Factory 的 QLoRA 支持 2/3/4/5/6/8 bit，经 AQLM / AWQ / GPTQ / LLM.int8 / HQQ / EETQ。
- 导出：Unsloth 可导出 GGUF、NVFP4、FP8；Axolotl 2026-09 加入 `axolotl export` 导出 GGUF（可选量化），供 llama.cpp 与 Ollama 部署。
- LLaMA-Factory 给出的显存估算（7B 模型）：全量 bf16/fp16 120GB，纯 bf16 60GB，LoRA 等 16GB，8-bit QLoRA 10GB，4-bit QLoRA 6GB，2-bit QLoRA 4GB。

## 三、训练与微调工具

### TRL（Hugging Face）

- 全称 Transformers Reinforcement Learning，定位「全面的基础模型后训练库」，支持 SFT、GRPO、DPO 等技术，构建在 transformers 生态之上，支持多种架构与模态。
- trainer：`SFTTrainer`、`GRPOTrainer`、`DPOTrainer`、`KTOTrainer` 等；每个 trainer 是 transformers Trainer 的轻量封装，原生支持 DDP、DeepSpeed ZeRO、FSDP。
- 扩展：借 Accelerate 从单 GPU 扩到多节点；与 PEFT 完整集成（量化 + LoRA/QLoRA）；集成 Unsloth 内核加速；提供命令行界面。
- 2026 年 README 动态：在单节点 8×B300 上对 Mistral Large 4（基于 FP8 权重）和 Reflection 的 Beam 做 LoRA SFT；Muse Spark Open 的 8 节点 LoRA 示例；经 PyTorch ROCm 支持 AMD Instinct GPU；经 TorchNeuron 支持 AWS Trainium。
- 版本：PyPI 最早 0.0.1（2020-03-30），1.0.0（2026-03-30），最新 1.17.1（2026-10-30）。v1.0 把 API 分成稳定区与 `trl.experimental` 孵化区，报道称已实现 75+ 种后训练方法（二手报道）。
- 下游：Unsloth、Axolotl、LLaMA-Factory 都把 trl 列为依赖。

### Unsloth

- Unsloth AI 开发；README 引用条目作者为 Daniel Han、Michael Han 与 Unsloth 团队，年份 2023。公司（二手报道）：Han 兄弟 2023 年在悉尼创办，Y Combinator 2024 夏季批次（S24），总部旧金山，Lightspeed 投资组合中列有该公司；种子轮金额各来源不一。
- README 现定位「第一个能运行和训练模型的桌面应用」：Unsloth Desktop（桌面）、Unsloth Studio（Web UI）、Unsloth Core（代码库）三种用法；支持 Windows / Linux / WSL / macOS，NVIDIA、AMD、Intel GPU、CPU 与 Vulkan。
- 微调：训练 LLM、扩散、TTS、嵌入等模型，「快 2 倍、省 70% 显存，无精度损失」；支持 RL、LoRA、QLoRA、全量微调、预训练、GRPO、DPO、FP8。免费 Colab 笔记本给出的数字：gpt-oss 20B 微调快 2 倍、省 70% 显存，GRPO 快 2 倍、省 80%。
- 运行与部署：本地运行 GGUF / MLX 等模型；`unsloth start claude|codex|...` 一条命令把 Claude Code、Codex、OpenCode、OpenClaw 等编程 Agent 接到本地模型；OpenAI 兼容 API；导出 GGUF、NVFP4、FP8。
- 依赖：PyTorch、Triton（自写内核）、bitsandbytes、transformers、PEFT、TRL。
- 版本号按日期：首个 PyPI 版本 2024.8（2024-08-04），最新 2026.11.2（2026-11-04）。

### Axolotl

- 自由开源的 LLM 后训练与微调工具，Apache-2.0；README 引用条目「Axolotl: Open Source LLM Post-Training」，作者为 Axolotl 维护者与贡献者，年份 2023；仓库在 axolotl-ai-cloud 组织。
- 特点：一个 YAML 配置贯穿数据预处理、训练、评估、量化、推理全流程。
- 训练方法：全量微调、LoRA、QLoRA、GPTQ、QAT（int8/int4/FP8/NVFP4/MXFP4）、FP8 混合精度、NVFP4/MXFP4 MoE LoRA、偏好调优（DPO、IPO、KTO、ORPO）、RL（GRPO、GDPO）、奖励模型 / 过程奖励模型（RM / PRM）。
- 性能：多样本打包（Multipacking）、Flash Attention 2/3/4、Liger Kernel、Cut Cross Entropy、ScatterMoE、序列并行、FSDP2 / DeepSpeed 多卡、Torchrun / Ray 多节点；ND 并行（CP + TP + FSDP，2025-07）；专家并行（DeepEP，2026-06；2026-09 起支持 torch all-to-all，不依赖 DeepEP）。
- 时间线：2025-01 奖励模型 / PRM；2025-02 GRPO；2025-03 序列并行、多模态微调；2025-05 QAT；2025-07 ND 并行、FP8 微调；2025-09 文本扩散训练；2026-04 异步 GRPO、Flash Attention 4、改为 uv 优先；2026-06 专家并行、Tinker 兼容 API 远程训练、BitNet 1.58-bit 微调；2026-09 GGUF 导出；2026-10 支持 Mistral Large 4、Reflection Beam（NVFP4 LoRA、专家并行）。
- 依赖：PyTorch ≥2.13、transformers、PEFT、TRL、Accelerate、bitsandbytes、Triton、torchao；可选 DeepSpeed、Ray、vLLM。需要 NVIDIA（Ampere 及以上）或 AMD GPU。

### LLaMA-Factory

- 作者 hiyouga（郑耀威，北京航空航天大学），论文「LlamaFactory: Unified Efficient Fine-Tuning of 100+ Language Models」，ACL 2024 系统演示，arXiv 2403.13372（2024-03-21 上线）。仓库名现写作 LlamaFactory。
- 功能：支持 LLaMA、LLaVA、Mistral、Mixtral-MoE、Qwen3、Qwen3-VL、DeepSeek、Gemma、GLM、Phi 等；方法覆盖（继续）预训练、（多模态）SFT、奖励建模、PPO、DPO、KTO、ORPO、SimPO；16-bit 全量、冻结微调、LoRA、2–8 bit QLoRA；优化器与算法 GaLore、BAdam、APOLLO、Adam-mini、Muon、OFT、DoRA、LongLoRA、LLaMA Pro、LoRA+、LoftQ、PiSSA；集成 FlashAttention-2、Unsloth、Liger Kernel、KTransformers；实验监控含自带的 LlamaBoard（Web UI）；推理用 vLLM 或 SGLang worker，提供 OpenAI 风格 API。
- 新模型「Day 0 / Day 1」支持：Qwen3、Qwen2.5-VL、Gemma 3、GLM-4.1V 等为 Day 0。
- 时间线：2023-08-11 支持 DPO；2023-10 NEFTune；2024-02 DoRA；2024-03 GaLore、LoRA+、ORPO、论文上线；2024-05 Ascend NPU、KTO、SimPO；2024-06 PiSSA；2025-01 APOLLO；2025-08 OFT / OFTv2；2025-10-26 支持 Megatron-core 训练后端（经阿里 ROLL 的 mcore_adapter）。
- 依赖：PyTorch、transformers、PEFT、TRL、Accelerate、datasets；可选 DeepSpeed、bitsandbytes、vLLM、flash-attn。
- PyPI 包 llamafactory 最新 0.9.5（2026-05-30）。

### verl

- 全称 Volcano Engine Reinforcement Learning for LLMs，由字节跳动 Seed 团队发起、verl 社区维护的 LLM 强化学习训练库，是论文 HybridFlow（EuroSys 2025，arXiv 2409.19256）的开源版本。Apache-2.0。
- 设计：混合控制器（hybrid-controller）编程模型，几行代码就能搭出 GRPO、PPO 等 RL 数据流；计算与数据依赖解耦，接入现有 LLM 基础设施；灵活的设备映射；3D-HybridEngine 在训练与生成阶段切换时对 actor 模型重分片，消除显存冗余、降低通信开销。
- 训练后端 FSDP、FSDP2、Megatron-LM；rollout 生成用 vLLM、SGLang 或 HF Transformers；兼容 Hugging Face 与 ModelScope 模型（Qwen3.5、Qwen3、Llama3.1、Gemma2、DeepSeek-LLM 等）。
- 算法：PPO、GRPO、GSPO、ReMax、REINFORCE++、RLOO、PRIME、DAPO、DrGRPO、KL_Cov / Clip_Cov；支持模型奖励与函数奖励（可验证奖励）；VLM 与多模态 RL；多轮工具调用；SPPO 等对齐配方。
- 规模：借专家并行扩展到 671B 模型、数百张 GPU；多 GPU LoRA RL；硬件支持 NVIDIA、AMD、华为昇腾。
- 用它训练的成果（README）：Doubao-1.5-pro 的 RL scaling 预览模型（2025-01，AIME pass@1 70.0）、DAPO（2025-03）、Seed-Thinking-v1.5（2025-04，AIME 2024 86.7）、VAPO（2025-04）；Mind Lab 用 verl + Megatron-Bridge 在 64 张 H800 上做万亿参数模型的 GRPO LoRA（2025-12）。
- 时间线：2024-08 HybridFlow 论文；2024-11-01 首个 PyPI 版本；2025-03 v0.3.0.post1（约 1.4 倍提速）、EuroSys 2025 发表；2026-01 迁入 verl-project 组织，recipe 目录拆成独立仓库 verl-recipe，首届线下 meetup（上海，火山引擎与 NVIDIA 主办）；2026-03 NVIDIA GTC26 演讲；2026-05 发布 uni-agent（大规模构建、运行、训练 LLM agent）、VeRL-Omni 预发布（扩散与全模态 RL）；2026-06 verl-SpeCo（RL 训练中协同训练推测解码草稿模型）；2026-08 verl-vla v0.1.0、VeRL-Tinker、VeRL-Omni v0.2.0；最新 PyPI 0.9.1（2026-09-20）。
- 生态：SGLang 的 README 把 verl 列为使用 SGLang 生成 rollout 的 RL 框架之一（见本库推理引擎调研）。
