# MCP 规范 2026-07-28 版

一句话：MCP 第五个协议修订版，也是当前版本（current）。核心变化是协议**无状态化**：去掉 `initialize` 握手和会话，每个请求自带版本与能力；服务端到客户端的请求改为“多轮往返请求”（MRTR）。

## 变更日志摘录（相对 2025-11-25）

### 重大变更

1. Streamable HTTP 去掉协议级会话和 `Mcp-Session-Id` 头；列表接口不再因连接而异；需要跨调用状态时，用服务端签发的句柄作为普通工具参数传递（SEP-2567）。
2. 去掉 `initialize` / `notifications/initialized` 握手。每个请求在 `_meta` 中携带 `io.modelcontextprotocol/protocolVersion` 和 `io.modelcontextprotocol/clientCapabilities`；客户端应附带 `clientInfo`，服务端应在结果中附带 `serverInfo`；版本不匹配时返回 `UnsupportedProtocolVersionError`（SEP-2575）。
3. 新增 `server/discover`，服务端必须实现：一次返回支持的版本、能力和身份信息（SEP-2575）。
4. 用 `subscriptions/listen` 取代 HTTP GET 端点和 `resources/subscribe` / `unsubscribe`：这是一条长连接的 POST 响应流，客户端按类型订阅变更通知（SEP-2575）。
5. 去掉 `ping`、`logging/setLevel`、`notifications/roots/list_changed`；日志级别改为在每个请求的 `_meta` 里用 `io.modelcontextprotocol/logLevel` 设置（SEP-2575）。
6. Tasks 从核心协议移出，成为官方扩展 `io.modelcontextprotocol/tasks`：用 `tasks/get` 轮询和 `tasks/update` 补充输入，取代阻塞式的 `tasks/result`，并去掉 `tasks/list`（SEP-2663）。
7. 引入多轮往返请求（MRTR），取代服务端主动发起的 `roots/list`、`sampling/createMessage`、`elicitation/create`。服务端返回 `InputRequiredResult`，客户端带上 `inputResponses` 重试原请求（SEP-2322）。
8. 所有结果都必须带 `resultType` 字段：`"complete"` 或 `"input_required"`（SEP-2322）。
9. 去掉 SSE 流的断点续传（`Last-Event-ID`）。流断开即丢失请求，客户端必须用新的请求 ID 重发（SEP-2575）。

### 次要变更（节选）

- 能力声明中新增 `extensions` 字段；`_meta` 中约定 OpenTelemetry 的 `traceparent` / `tracestate` / `baggage`。
- Streamable HTTP POST 请求必须带 `Mcp-Method` / `Mcp-Name` 头；工具参数可通过 `x-mcp-header` 映射为 `Mcp-Param-{Name}` 头（SEP-2243）。
- 列表类结果和 `resources/read` 必须带 `ttlMs` 和 `cacheScope`（`public` / `private`），即新的 `CacheableResult`（SEP-2549）。`tools/list` 应按确定顺序返回。
- 授权方面：应带 `iss` 参数并由客户端校验（RFC 9207）；凭证与签发它的授权服务器绑定；DCR 必须声明 `application_type`。
- `inputSchema` / `outputSchema` 放开到完整的 JSON Schema 2020-12。
- 错误码重新分配：`-32020` 到 `-32099` 保留给 MCP 规范（HeaderMismatch `-32020`、MissingRequiredClientCapability `-32021`、UnsupportedProtocolVersion `-32022`）；资源不存在改为 `-32602`。

### 弃用

- Roots、Sampling、Logging 特性（SEP-2577）。
- HTTP+SSE 传输（2024-11-05 版的旧传输）。
- `includeContext` 的 `"thisServer"` / `"allServers"` 取值。
- OAuth 动态客户端注册（DCR），改用 Client ID Metadata Documents（CIMD）。

### 治理

- 特性生命周期政策：Active → Deprecated → Removed，弃用窗口至少 12 个月（加急情况至少 90 天）（SEP-2596）。
- SEP 改为基于 PR 的流程（SEP-1850）。
