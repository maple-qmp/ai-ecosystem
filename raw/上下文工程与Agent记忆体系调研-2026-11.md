# 上下文工程与 Agent 记忆体系调研（2026-11）

上下文工程管理每次推理能看到的信息；Agent 记忆管理跨步骤、跨会话保留和更新的信息。两者通过“写入—存储—检索—组装—使用—修正”连接。保存历史并不保证正确召回，正确召回也不保证正确回答。

本报告为中文研究综合，不是网页原文存档。检索日期为 2026-11-06；依据官方工程文章、框架文档和原始论文，不做模型排行榜或产品效果背书。文中的落地方案是用于验证的设计示例，未实施、未跑性能实验，不代表用户已作出的判断。另一专题见 [[raw/AI应用评测与可观测性调研-2026-11]]。

## 1. 来源与证据边界

- **C1**：[Anthropic：Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)，2025-09-29。支持上下文管理、即时检索、压缩、外部笔记和子 Agent 隔离；属于厂商工程经验，不是所有模型的性能定律。
- **C2**：[LangGraph：Memory overview](https://docs.langchain.com/oss/python/concepts/memory)，滚动文档，2026-11-06 查阅。支持线程级与跨线程记忆、语义/情景/程序性记忆、同步与后台写入的区分。`/langgraph/memory` 当前返回同主题内容，本报告按一份来源去重。
- **C3**：[LongMemEval 原始论文](https://arxiv.org/abs/2410.10813)及[作者代码仓库](https://github.com/xiaowu0162/LongMemEval)。支持五类记忆能力、索引/检索/读取分阶段诊断；论文内商业系统实验发生在 2024 年，不能推断为 2026 年产品能力。
- **C4**：[Anthropic：Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)，2026-01-09。用于实验隔离、重复试验、结果与轨迹分离的设计依据。

## 2. 先拆开六个容易混淆的概念

| 概念 | 管理的对象 | 不应混同为 |
| --- | --- | --- |
| 提示词工程 | 指令、示例、输出约束如何表达 | 整个运行状态的管理 |
| 上下文工程 | 当前调用的指令、工具、历史、检索证据与状态 | 单纯增加窗口长度 |
| 短期记忆 | 当前线程的历史和任务状态 | 必须放在进程 RAM 内的临时数据 |
| 长期记忆 | 跨线程的事实、偏好、经历与规则 | 无差别保存所有原始对话 |
| RAG | 检索外部资料并为生成提供证据 | 自动负责记忆更新和冲突解决 |
| 检查点 | 持久保存运行状态以便恢复 | 让模型理解全部历史的机制 |

前三类边界来自 C1、C2。C2 中短期记忆可通过 checkpointer 存入数据库，因此“短期”主要描述使用范围，不是磁盘保留时长。RAG 可用于记忆检索，但完整记忆系统还需决定写什么、何时更新、谁能读以及如何撤销（综合 C2、C3）。

## 3. 上下文工程的五类操作

以下按 C1 的工程方法归纳，而非某个 SDK 的统一接口。

| 操作 | 可落地做法 | 代价与失败模式 |
| --- | --- | --- |
| 选择 | 按任务选择工具、文档和必要历史；保留来源位置 | 漏召回重要约束，或把相似但无关内容当证据 |
| 外置 | 大段结果存文件，当前上下文只留摘要和路径 | 路径失效、版本变化，或后续没有重新读取 |
| 压缩 | 保留目标、已做决定、未解决问题和必要证据 | 摘要遗漏条件、日期与否定词，形成不可见失真 |
| 隔离 | 子任务使用独立上下文，仅回传必要结果 | 子任务信息不足，汇总者收不到限定条件 |
| 按需加载 | 先读目录和元信息，再取所需全文 | 多轮工具调用增加延迟，探索可能走入死路 |

C1 同时强调清晰指令、少量有代表性的示例与职责明确的工具。所谓精简，是移除低信号内容，不是把必要约束删到最短。其“预取部分资料 + 后续即时检索”的混合策略，提供了比全量塞入或完全自主搜索更细的选择空间。

## 4. 记忆不是单一技术：两个分类轴

**按范围**：线程内状态与跨线程存储。**按内容**：事实型（semantic）、经历型（episodic）、操作规则型（procedural）。两轴可以组合，且“语义记忆”不等于“向量语义搜索”。这些区分来自 C2。

| 内容 | 知识库助手中的示例 | 候选存储方式 |
| --- | --- | --- |
| 事实 / 偏好 | 用户明确要求报告用中文 | 有字段的配置或个人资料 |
| 经历 | 上次一次检索漏掉了旧版本的限制 | 带证据链接的任务记录 |
| 操作规则 | 发布前检查断链和来源 | 经审核的工作流说明 |
| 当前任务状态 | 已读哪些来源、哪些结论待核实 | 线程状态或进度文件 |

表中的存储方式是设计示例，不是通用最优方案。C2 提供两种事实组织方式：持续更新的 profile 易于整体读取，但变大后更难准确修改；分散 collection 容易追加，却需要处理重复、冲突、更新与检索。

### 写入时机

- **同步写入（hot path）**：新信息可立即用于下一步，但会增加主流程的延迟与决策负担。[C2]
- **后台写入**：把整理工作移出主响应路径，但其他线程可能读到旧状态；要定义触发条件与可见性。[C2]
- **知识库助手设计示例**：用户明确纠正的偏好同步保存；冗长任务经历后台提炼。对“已保存”的答复，应以实际存储成功为条件，而不是以模型生成了保存意图为条件。

## 5. 一个可检查的记忆生命周期

以下是由 C2 的存储模型与 C3 的知识更新、时间推理能力要求推导的设计方案，不是协议标准。

1. **提取候选**：识别事实、来源、作用范围；区分用户陈述、网页内容和模型推断。
2. **检查冲突**：比较已有记录；新增事实与纠正旧事实采用不同操作。
3. **保存版本**：至少记录 `id`、`namespace`、`content`、`source_ref`、`observed_at`、`valid_from`、`status`；必要时记录 `supersedes`、到期时间与版本号。
4. **受控召回**：先限定用户/项目与权限，再搜索；存储命名空间本身不是授权检查。
5. **组装上下文**：把有效记录、证据位置和日期一起交给模型；冲突未解决时呈现冲突。
6. **修正或撤销**：纠正后使旧版本退出当前检索；保留审计记录时，也要按保留策略处理访问范围。

`observed_at` 表示系统何时获知，`valid_from` 表示事实何时生效，两者不能总是互换。删除还需考虑向量索引、摘要和缓存中是否残留同一事实。这些字段与检查应通过具体业务测试验证。

## 6. 方法选型：先用任务约束缩小范围

| 条件 | 可先验证的组合 | 验证重点 |
| --- | --- | --- |
| 材料少、单次问答 | 必要全文 + 明确来源 | 是否比引入检索更简单且同样准确 |
| 文档多、更新频繁 | 元信息预取 + 搜索 + 按需全文 | 漏召回、旧版本命中、工具调用延迟 |
| 长任务反复接续 | 检查点 + 进度笔记 + 历史压缩 | 重启后是否保留目标、约束与证据 |
| 跨会话个性化 | 结构化偏好 + 有范围的长期存储 | 新偏好覆盖旧偏好、用户隔离、可撤销 |
| 多方向研究 | 独立子任务上下文 + 有来源的汇总 | 汇总是否丢掉条件、冲突和不确定性 |

这是待验证的选型路线，不能由厂商示例推断必然提效。库中的 [[concepts/observational-memory|观察式记忆]] 是一种具体实现；它的厂商自报分数不能代替在相同模型、预算、数据和评分器下的对照实验。

## 7. 贯穿案例：让 AI 生态知识库支持可靠问答

**目标示例**：“比较三个 Agent 框架，并说明哪些结论只适用于某个版本。”现有文件不作改造，以下仅为应用设计。

1. 读取用户问题、知识库约定和相关地图，不默认把整个库载入上下文。
2. 根据名称、别名与层级寻找实体页，再读取必要的来源页和原始调研。
3. 给每条证据保留文件路径、章节、日期和版本范围；材料冲突时明确标注。
4. 当前任务状态记录已比较的维度和未查清的问题；这属于短期状态。
5. 只有明确且可持续使用的偏好进入长期记忆；不要把某次问题误存成永久偏好。
6. 长任务压缩时保留用户限制、已核实证据、未解决冲突和文件引用。继续执行前重新读取可能变化的文件。
7. 回答附可打开的证据链接，资料不足时说明缺口，避免用记忆摘要冒充原始来源。

### 可复现的对照设计（未运行）

- A：完整历史；B：最近历史 + 摘要；C：任务状态 + 有范围的检索记忆。
- 固定模型、提示、知识库快照、问题集、最大调用预算；每组从相同空白或预置记忆状态启动。
- 按信息提取、多会话组合、知识更新、时间推理、无法回答五类分别统计；不要只看平均分。这五类来自 C3。
- 同时记录答案正确性、证据支撑、约束保留、输入 token、端到端延迟和成本。
- 增加压缩前后对照、跨用户干扰及纠正旧事实的测试；不能让 A 的答案进入 B 的记忆造成泄漏。[实验隔离依据 C4]

## 8. 如何定位“明明记过却答错”

C3 把系统拆为索引、检索和读取三个阶段，支持如下诊断：

| 现象 | 首先检查 | 应避免的直接结论 |
| --- | --- | --- |
| 事实从未进入存储 | 候选提取、写入失败、覆盖记录 | 一定是检索器不好 |
| 记录存在但未召回 | namespace、过滤条件、时间范围、检索 query | 一定要换大模型 |
| 召回正确但答案错误 | 证据组装、冲突、摘要、生成环节 | 检索分数高就算成功 |
| 旧偏好压过新偏好 | 生效时间、替代关系、缓存与摘要 | 长期记忆越多越好 |
| 无证据仍肯定回答 | 拒答用例、评分准则与提示 | 流畅等于可靠 |

LongMemEval 有 500 个问题，可借鉴其能力分类；它主要测试长期交互记忆，不覆盖所有企业权限、工具执行和工作流恢复问题。历史实验百分比不应脱离测试设置引用为当前能力结论。[C3]
