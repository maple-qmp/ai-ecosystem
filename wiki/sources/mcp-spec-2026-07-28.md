# MCP 规范 2026-07-28 版

## Summary

[[concepts/model-context-protocol|MCP]] 的第五个协议修订版，于 2026-07-28 发布，是当前版本。这一版把 MCP 从“有状态会话协议”改成了**无状态协议**：去掉 `initialize` 握手和 `Mcp-Session-Id`，每个请求自带协议版本和客户端能力；服务端需要客户端输入时，改用[[concepts/multi-round-trip-requests|多轮往返请求（MRTR）]]；推送通知统一走 `subscriptions/listen`；Tasks 改为官方扩展。这些改动的目的，是让 MCP 服务器可以部署在普通的无状态负载均衡和网关后面。

## Key Points

- **无状态核心**：没有握手、没有会话；版本、能力、身份信息都放在每个请求的 `_meta` 里
- **`server/discover`**：服务端必须实现，用于预先选择版本，也用作 stdio 下的兼容性探测
- **MRTR**：sampling、elicitation、roots 都通过 `InputRequiredResult` 加客户端重试来完成，服务端不再主动发请求
- **`subscriptions/listen`**：取代 HTTP GET 流和 `resources/subscribe`
- **`resultType`**：所有结果必带，取值为 `complete`、`input_required`，或扩展定义的 `task`
- **网关友好**：`Mcp-Method`、`Mcp-Name`、`Mcp-Param-*` 请求头，以及 `ttlMs` / `cacheScope` 缓存提示
- **断流即失败**：去掉 `Last-Event-ID` 续传，流断开后需要用新 ID 重发请求
- **弃用**：Roots、Sampling、Logging、HTTP+SSE 传输、动态客户端注册（DCR）
- **治理**：特性生命周期政策，弃用窗口至少 12 个月
